# Harshil Agrawal: Portfolio & ML Demo

A FastAPI portfolio site designed as a Jupyter notebook, with a deployed Random Forest microservice. Code cells show `In [n]` / `Out[n]`; a **Code** switch hides the code and keeps every result, so the site reads fine for non-technical visitors.

## Features

- **Notebook home (`/`):** about, an evidence table, one case cell per project, a live model cell and contact. Cells "run" as they scroll into view; with reduced motion, no JavaScript or in print, everything is visible at once.
- **Live model (`/demo`):** sliders and presets that call `POST /predict`, plus the model card: held-out accuracy against a baseline, feature importances and a `curl` example.
- **Resume (`/resume`):** HTML resume with print styles and the PDF generated by `scripts/generate_resume_pdf.py`.
- **One source of truth:** `PROJECTS` in `app/main.py` renders the site and `/api/projects`.
- Self-hosted fonts (Instrument Sans, JetBrains Mono, both OFL), light and dark themes, no analytics.

## Stack

- FastAPI + Jinja2, one stylesheet (`app/static/site.css`) and one script (`app/static/notebook.js`)
- scikit-learn Random Forest
- Docker
- Google Compute Engine (Always Free)

## Quick Start

The Dockerfile runs Python 3.11, and the pinned FastAPI needs it.

```bash
uv venv -p 3.11 .venv311
uv pip install -p .venv311 -r requirements.txt

# Train the model (synthetic data; prints accuracy and writes ml/model.joblib)
.venv311/bin/python ml/train_model.py

# Run locally
.venv311/bin/uvicorn app.main:app --reload --port 8000
```

Open http://localhost:8000

## Tests

Three suites under `tests/`, all on the standard library's `unittest`:

- `test_unit.py`: project facts, the model and its metadata, the resume generator (the committed PDF must match a fresh build), CSS and font rules.
- `test_integration.py`: the real app on uvicorn over HTTP. Routes, redirects, the 404 page, `/predict`, page content, every local link and asset.
- `test_browser.py`: `notebook.js` in headless Chromium (Playwright). Run-on-scroll, the Code switch, the live model, keyboard, copy, theme, phone layout. Skipped if Playwright isn't installed.

```bash
uv pip install -p .venv311 -r requirements-dev.txt && .venv311/bin/playwright install chromium
.venv311/bin/python -m unittest discover tests
```

`scripts/check_site.py` is a smaller smoke check that also runs against production:

```bash
python scripts/check_site.py https://harshil-portfolio.duckdns.org
```

## Routes

- `GET /`: the notebook home page
- `GET /demo`: the live model and its model card
- `GET /resume`: the resume
- `GET /projects`, `GET /contact`: permanent redirects to `/#work` and `/#contact`
- `POST /predict`: defect prediction from five form fields; out-of-range input returns 422
- `GET /health`: health check
- `GET /api/projects`: the `PROJECTS` data that renders the site

## Deployment

### Google Cloud Always Free

1. Create an Ubuntu **e2-micro** VM in `us-west1`, `us-central1`, or `us-east1`, and allow inbound HTTP traffic.
2. SSH to the VM, then install Docker, Docker Compose, and Git:

   ```bash
   sudo apt-get update
   sudo apt-get install -y docker.io docker-compose-v2 git
   sudo systemctl enable --now docker
   ```

3. Clone this repository and start the app:

   ```bash
   git clone https://github.com/Harshil411/portfolio.git
   cd portfolio
   sudo docker compose up -d --build
   ```

4. Confirm the service is running at `http://YOUR_VM_IP/health`.

The included `compose.yaml` restarts the portfolio after a VM reboot and serves HTTPS automatically when the configured hostname resolves to the VM. Keep the VM in the listed US regions and within the e2-micro/disk/egress free-tier limits.

### Automatic deployments from GitHub

`.github/workflows/deploy.yml` updates the VM whenever a commit reaches `main`. It uses a dedicated SSH key instead of granting GitHub Actions broad Google Cloud permissions.

One-time setup:

1. On the VM, create a deploy key and authorize its public half for the VM user that owns `~/portfolio`:

   ```bash
   ssh-keygen -t ed25519 -f ~/.ssh/github_actions_portfolio -N ""
   cat ~/.ssh/github_actions_portfolio.pub >> ~/.ssh/authorized_keys
   base64 -w 0 ~/.ssh/github_actions_portfolio
   ssh-keyscan -H YOUR_VM_IP
   ```

2. In GitHub: **Settings → Secrets and variables → Actions**, add these repository secrets:

   - `GCP_SSH_PRIVATE_KEY`: the one-line Base64 output from `base64 -w 0 ~/.ssh/github_actions_portfolio`
   - `GCP_SSH_KNOWN_HOSTS`: output from `ssh-keyscan -H YOUR_VM_IP`

3. In the same page, add these repository variables:

   - `GCP_SSH_HOST`: the VM external IP or hostname
   - `GCP_SSH_USER`: the Linux account that owns `~/portfolio`

Keep the SSH private key only in GitHub Secrets; do not commit it. The workflow verifies the local `/health` endpoint after each deployment. If the VM's ephemeral IP changes, update both the DuckDNS record and `GCP_SSH_HOST`.

## Model

Random Forest trained on 5,000 synthetic manufacturing sensor samples (4,000 train, 1,000 held out). Features: temperature, humidity, pressure, vibration, RPM. Held-out accuracy 0.881, against 0.698 for always guessing "no defect".
